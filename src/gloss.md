контейнер :: изолированный процесс (или группа процессов), запущенный на ядре хозяина; видит только свои файлы, процессы и сеть
образ :: неизменяемый набор файлов и настроек, из которого запускают контейнеры; «чертёж» контейнера
виртуальная машина (VM) :: целый компьютер в программе: со своим ядром и системой; тяжелее контейнера
клиент (docker) :: программа в терминале, которая отправляет команды демону
демон (dockerd) :: фоновая программа Docker: управляет образами, контейнерами, сетями и томами
containerd :: менеджер жизненного цикла контейнеров, работает под демоном
runc :: маленькая программа, которая создаёт изолированный процесс средствами ядра Linux
namespace :: механизм ядра: ограничивает, что процесс видит (процессы, сеть, файлы, имя хоста)
cgroup :: механизм ядра: ограничивает, сколько ресурсов процесс может использовать (память, процессор)
registry :: хранилище образов; главное публичное — Docker Hub
Docker Hub :: публичный registry на hub.docker.com
GHCR :: GitHub Container Registry, адрес <code>ghcr.io</code>; хранилище образов, привязанное к аккаунту GitHub
Docker Desktop :: приложение для Mac и Windows: Linux-VM с Docker Engine плюс клиент и графический интерфейс
Docker Engine :: демон и всё, что нужно для запуска контейнеров; ставится прямо в Linux
context :: настройка клиента: к какому демону подключаться (<code>docker context ls</code>)
сокет :: файл или адрес, через который клиент разговаривает с демоном
PID :: номер процесса; главный процесс контейнера имеет PID 1, и когда он завершается, контейнер останавливается
сигнал :: сообщение процессу от системы: SIGTERM — «закончи работу», SIGKILL — «убит немедленно»
код выхода :: число, с которым завершился процесс: 0 — успех; 137 = 128+9 (SIGKILL), 143 = 128+15 (SIGTERM)
слой :: часть образа, неизменяемый набор изменений файловой системы; образ состоит из стопки слоёв
слой записи :: тонкий слой поверх образа, куда пишет контейнер; исчезает вместе с контейнером
тег :: метка версии образа после двоеточия (<code>alpine:3.22</code>); без указания подставляется <code>latest</code>
digest :: неизменный отпечаток содержимого образа (<code>sha256:…</code>); в отличие от тега, не меняется
манифест :: небольшой JSON-документ в registry: из каких слоёв состоит образ
Dockerfile :: текстовый рецепт сборки образа; каждая инструкция создаёт слой
контекст сборки :: папка, содержимое которой <code>docker build</code> отправляет демону для <code>COPY</code>
.dockerignore :: список файлов, которые не попадают в контекст сборки
кэш сборки :: сохранённые результаты слоёв; пересборка идёт с первого изменившегося слоя
multi-stage :: Dockerfile с несколькими <code>FROM</code>: сборка в одном этапе, в итоговый образ копируется только результат
BuildKit :: современный движок сборки образов, включён по умолчанию; команда <code>docker buildx</code>
distroless :: образы без оболочки и менеджера пакетов: меньше поверхность атаки
Alpine :: крошечный Linux-образ на библиотеке musl
musl / glibc :: две реализации стандартной библиотеки C; программа под одну может не работать на другой
ENTRYPOINT / CMD :: то, что запускается в контейнере: итоговая команда = ENTRYPOINT + CMD
exec-форма / shell-форма :: <code>CMD ["a","b"]</code> запускает программу напрямую, <code>CMD a b</code> — через <code>/bin/sh -c</code>
exec "$@" :: в конце entrypoint-скрипта: заменить скрипт приложением, чтобы сигналы доходили до него
ARG / ENV :: переменные: ARG — только при сборке, ENV — ещё и в запущенном контейнере
HEALTHCHECK :: команда, которую Docker периодически запускает, чтобы пометить контейнер healthy или unhealthy
non-root :: запуск процесса от обычного пользователя вместо root
capabilities :: отдельные «права» root в Linux; <code>--cap-drop ALL</code> убирает все
read-only :: файловая система контейнера только для чтения (<code>--read-only</code>)
tmpfs :: папка в оперативной памяти; исчезает при остановке контейнера
CVE :: номер известной уязвимости; сканер (Trivy) ищет их в пакетах образа
SBOM :: перечень компонентов образа (какие пакеты внутри)
том (volume) :: хранилище данных под управлением Docker, живёт отдельно от контейнера
bind mount :: подключение конкретной папки или файла хоста внутрь контейнера
анонимный том :: том со случайным именем, который создаёт инструкция VOLUME или флаг -v без имени; легко «осиротеть»
UID / GID :: номер пользователя / группы в Linux; файлы подписаны числами, а не именами
bridge :: сеть по умолчанию на одном хосте; в пользовательской bridge работает DNS по именам
встроенный DNS Docker :: сервер <code>127.0.0.11</code> внутри контейнера: превращает имя контейнера или сервиса в IP
публикация порта (-p) :: проброс порта хоста в порт контейнера (NAT); без него контейнер снаружи недоступен
NAT :: трансляция адресов: правило, по которому трафик на порт хоста перенаправляется в контейнер
Compose :: инструмент описания и запуска нескольких контейнеров одним файлом
сервис :: «роль» приложения в Compose (web, api, db): описание, как запускать контейнер
проект :: группа сервисов Compose; имя по умолчанию — имя папки, префикс имён контейнеров, сетей, томов
интерполяция :: подстановка <code>${VAR}</code> в <code>compose.yaml</code> до запуска
.env :: файл рядом с <code>compose.yaml</code> со значениями переменных для интерполяции; в git не коммитится
profiles :: переключатели: сервис с профилем запускается только когда профиль включён
override :: файл <code>compose.override.yaml</code>, который подмешивается к основному автоматически
якорь (&, *) :: способ YAML один раз описать блок и вставить его повторно
replica :: копия сервиса, запущенная флагом <code>--scale</code>
restart policy :: правило перезапуска: no, on-failure, always, unless-stopped
OOM :: нехватка памяти: ядро убивает процесс, признак — код 137 и <code>OOMKilled=true</code>
smoke test :: быстрая проверка, что система вообще работает
CI/CD :: автоматическая сборка, проверка и выкладка при каждом изменении кода
workflow :: файл GitHub Actions в <code>.github/workflows/</code>: когда и что запускать
GITHUB_TOKEN :: встроенный токен GitHub Actions; хватает для публикации в GHCR из workflow
семантическая версия :: <code>MAJOR.MINOR.PATCH</code>: несовместимое.новое.исправление
production hell :: учебный стенд, где стек намеренно сломан в нескольких местах; нужно найти и исправить без подсказок
starter :: чистая проверенная копия проекта без секретов и черновиков, с которой начинают следующие лабы
